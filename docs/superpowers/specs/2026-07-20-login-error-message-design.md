# 登录失败提示适配设计

## 背景

`LoginServiceImpl` 现在会通过响应中的 `error_message` 区分登录失败原因，例如被封禁账号返回“该账号已被封禁”。当前登录页在失败回调中始终显示“用户名或密码错误”，导致后端提供的具体原因丢失。

## 目标

- 登录业务失败时，向用户展示后端返回的 `error_message`。
- 网络异常或响应中没有可用错误消息时，展示“登录失败，请稍后重试”。
- 保持现有成功登录、Token 保存和跳转流程不变。

## 设计

仅调整 `UserAccountLoginView.vue` 的登录失败回调：接收 Vuex `login` action 传回的响应，依次读取业务响应的 `error_message` 和 jQuery 异常响应中的 `responseJSON.error_message`，最后使用通用兜底文案。

Vuex `login` action 已经在业务失败和请求失败时把响应对象交给页面，因此无需修改状态管理层，也不在前端重复维护封禁等业务状态映射。

## 错误处理

| 场景 | 页面提示 |
| --- | --- |
| 后端返回 `error_message: "该账号已被封禁"` | 该账号已被封禁 |
| 后端返回其他非成功 `error_message` | 原样展示该消息 |
| HTTP 异常响应的 JSON 中含 `error_message` | 展示该消息 |
| 响应缺失或没有 `error_message` | 登录失败，请稍后重试 |

## 验证

- 运行前端项目现有的静态检查或构建命令。
- 检查登录失败回调不再写死用户名/密码错误文案。
- 检查成功登录分支未发生变化。

## 范围

本次不修改后端登录逻辑、不新增错误码体系，也不重构其他请求的错误提示。
