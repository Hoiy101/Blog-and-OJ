# 纯所见即所得 Markdown 图片编辑设计

## 背景与目标

当前博客正文以 Markdown 字符串存入数据库，正文图片存入 MinIO。编辑器使用 Ace 显示 Markdown 源码，并通过“编辑/预览”标签切换查看渲染结果。

本次改造将编辑器变为纯所见即所得模式：用户在同一个编辑区域内直接编辑排版后的正文、查看上传后的图片、拖拽调整图片尺寸，并可通过键盘自然删除图片。数据库仍保存 Markdown，不改后端正文模型，也不在删除正文图片引用时清理 MinIO 文件。

## 方案选择

采用原生 `contenteditable` 实现，不引入新的编辑器依赖。

选择原因：

- 与项目现有自研 Markdown 渲染器和安全策略保持一致。
- 避免新增依赖、构建体积和 npm 网络可用性风险。
- 可以精确控制图片占位、缩放、删除和 Markdown 序列化规则。

不采用以下方案：

- TipTap 等第三方编辑器：交互更成熟，但需要新增依赖和自定义 Markdown 扩展。
- Ace 上叠加图片：无法提供真正自然的所见即所得光标与图片交互。

## 数据格式与兼容性

数据库继续保存 Markdown 字符串，不保存编辑器 HTML。

普通图片沿用标准 Markdown：

```markdown
![说明](https://example.com/image.png)
```

拖拽调整过尺寸的图片使用项目内扩展语法：

```markdown
![说明](https://example.com/image.png){width=40%}
```

规则如下：

- 未声明宽度的旧图片默认显示为正文容器宽度的 25%。
- 宽度保存为整数百分比，合法范围为 10%～100%。
- 非数字、越界或格式不合法的宽度回退为 25%。
- 博客详情页和编辑器使用同一套宽度解析规则。
- 图片保持居中，高度根据原图比例自动计算。

## 组件与职责

### MarkdownEditor.vue

- 使用原生 `contenteditable` 作为唯一正文编辑区域。
- 接收数据库 Markdown，通过安全渲染转换为可编辑 DOM。
- 监听有效编辑操作，将 DOM 序列化回 Markdown，并通过 `v-model` 更新正文。
- 保留粗体、标题、链接和图片上传工具栏。
- 管理光标、图片选择、拖拽手柄、键盘删除和粘贴清理。
- 编辑器辅助元素不参与 Markdown 序列化。

### markdown.mjs

- 扩展图片语法解析，识别可选的 `{width=N%}`。
- 为图片输出经过校验的宽度元数据和样式。
- 继续转义原始 HTML，拒绝危险 URL 和事件属性。

### wysiwygMarkdown.mjs

新增独立的无 DOM 业务工具和 DOM 序列化边界：

- 图片宽度规范化与范围限制。
- Markdown 图片语法生成、更新和删除。
- 安全可编辑 DOM 到 Markdown 的序列化。
- 光标与图片相邻关系判断。

可独立测试的纯函数与浏览器 DOM 操作分离，避免所有逻辑堆积在 Vue 组件内。

### MarkdownContent.vue

- 继续负责博客详情和只读内容渲染。
- 根据 Markdown 中的宽度元数据展示图片。
- 保持占位加载、失败回退、请求缓存、竞态保护和遮罩大图功能。

## 编辑与图片交互

### 上传与显示

1. 用户点击上传图片并选择文件。
2. 前端沿用现有接口上传到 MinIO。
3. 上传成功后，在当前光标位置插入图片节点；没有有效选区时插入到正文末尾。
4. 图片先展示 `violation-del.png` 占位图。
5. 原图预加载成功后替换占位图；失败时继续显示占位图。
6. 同步生成图片 Markdown，初始宽度为默认 25%，可省略宽度扩展。

新建博客没有 `blogId` 时仍禁止上传图片，并显示“先创建博客，再修改文章上传图片”。

### 选择与缩放

- 单击编辑区图片时选中该图片，显示选中边框和左右缩放手柄。
- 从图片左右手柄拖动时，根据指针位置和编辑区宽度实时计算百分比。
- 实时宽度限制在 10%～100%，并保持图片纵横比。
- 松开指针后，将整数宽度写回编辑 DOM 和 Markdown。
- 点击编辑区其他位置或按 Escape 取消图片选择。
- 编辑状态下单击图片用于选择和缩放，不打开遮罩大图；只读详情页仍可单击打开大图。

### 删除

以下操作删除整张图片节点及其 Markdown 引用：

- 图片已选中时按 Backspace。
- 图片已选中时按 Delete。
- 折叠文字光标位于图片节点正后方时按 Backspace。
- 折叠文字光标位于图片节点正前方时按 Delete。

删除只更新正文内容，不请求后端删除 MinIO 对象。删除后把光标放到原图片位置附近，保证用户可以继续输入。浏览器原生撤销/重做应能恢复或再次删除图片节点，随后重新同步 Markdown。

## Markdown 与 DOM 同步

- 非编辑器自身触发的外部 `modelValue` 变化时，编辑器把 Markdown 重新渲染为安全 DOM。
- 用户输入、格式化、粘贴、上传、缩放或删除后，将可编辑 DOM 序列化为 Markdown。
- 使用同步保护标记识别编辑器自身的 `v-model` 回传；本地回传不重建 DOM，以保留选区和浏览器撤销栈，并避免 `modelValue → DOM → modelValue` 循环。
- 输入法组合期间不执行破坏性的 DOM 重建，组合结束后再同步 Markdown。
- 图片选中边框、手柄、占位加载状态等只属于 UI，不进入 Markdown。
- 快速外部更新使用版本号防止旧的异步图片加载结果覆盖新内容。

## 粘贴与安全

- 粘贴纯文本时按普通文本插入。
- 粘贴富文本时清理 DOM，只保留编辑器支持的结构：标题、段落、换行、列表、引用、粗体、斜体、删除线、链接、行内代码、代码块、表格和图片。
- 移除脚本、样式、事件处理属性、未知标签和编辑器辅助元素。
- 链接与图片 URL 继续只允许 HTTP、HTTPS、站内相对路径和锚点。
- 图片宽度只接受规范化后的整数百分比，不直接信任粘贴 HTML 的 `style`。
- DOM 到 Markdown 的序列化仅遍历允许的结构，未知节点降级为安全文本或其安全子内容。

## 异常处理

- 图片上传失败时保留现有正文和光标位置，并在工具栏显示错误。
- 原图加载失败时保持失效占位图，不影响 Markdown 中保存的原地址。
- 非法图片宽度回退为 25%。
- 组件卸载或正文快速切换时取消旧版本 DOM 更新的生效资格。
- 删除操作不依赖 MinIO，因此网络失败不会阻止删除图片引用。

## 测试策略

前端单元测试覆盖：

- 标准图片和带宽度图片的 Markdown 渲染。
- 默认宽度、合法宽度、越界宽度和非法宽度。
- DOM 与 Markdown 双向转换的主要支持结构。
- 编辑器辅助节点不会进入 Markdown。
- 图片缩放计算及 10%～100% 边界。
- 图片选中后的 Backspace/Delete 删除。
- 光标位于图片后一格时 Backspace 删除。
- 光标位于图片前一格时 Delete 删除。
- 上传成功后在编辑区立即插入并显示图片。
- 粘贴危险 HTML 时的清理行为。
- 快速更新下的图片加载竞态和相同 URL 缓存。

集成验证包括：

- 新建博客仍无法在首次保存前上传图片。
- 编辑已有博客可上传、缩放、删除引用并保存。
- 重新打开编辑器后尺寸保持一致。
- 博客详情按保存尺寸展示，并保留遮罩查看大图。
- 前端单元测试、ESLint、生产构建和后端全量测试全部通过。

## 非目标

- 不删除或回收正文中不再引用的 MinIO 图片。
- 不修改 MinIO 硬编码配置。
- 不改变数据库结构或后端博客正文接口。
- 不引入多人协同编辑、图片裁剪、旋转或像素级尺寸输入。
