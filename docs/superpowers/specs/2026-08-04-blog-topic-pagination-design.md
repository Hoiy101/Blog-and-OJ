# 博客与题库分页查询设计

## 目标

为博客列表和题库列表增加数据库分页查询。前端每次只请求并保存当前页数据，不再一次性加载全量列表。

- 博客每页固定 10 条。
- 题库每页固定 20 条。
- 搜索覆盖数据库中的全部匹配数据，而不是仅搜索当前页。
- 分页控件位于列表卡片底部右侧，由上一页左箭头、当前页数字输入框和下一页右箭头组成。

## 后端接口

保留现有查询路径，通过 URL 查询参数传递当前页和搜索关键词：

```text
GET /user/bot/all/getlist/?page=2&keyword=Java
GET /oj/topic/getlist/?page=3&keyword=数组
```

参数约束：

- 公开博客页和题库页始终在 URL 中携带 `page`；它是从 1 开始的正整数，非法时按第 1 页处理。
- `keyword` 可省略或为空；后端去除首尾空白后再筛选。
- 每页条数由后端固定，前端不能覆盖：博客 10 条，题库 20 条。

`/oj/topic/getlist/` 同时被现有题库管理页调用。为避免破坏该页面，无 `page` 参数的旧请求继续返回完整题目数组；携带 `page` 的公开题库页请求返回下述分页结构。公开题库页不得省略 `page`。

博客分页请求和携带 `page` 的题库请求统一返回以下结构：

```json
{
  "records": [],
  "currentPage": 1,
  "pageSize": 10,
  "total": 35,
  "totalPages": 4
}
```

- `records` 只包含当前页记录。
- `total` 是应用关键词筛选后的总记录数。
- `totalPages` 是应用关键词筛选后的总页数。
- 没有匹配数据时，`records` 为空、`total` 和 `totalPages` 均为 0，`currentPage` 保持为 1。
- 请求页码超过最后一页时，后端修正到最后一页并返回该页；空结果仍返回第 1 页。

## 查询与排序

博客：

- 搜索范围为标题和简介。
- 使用 MyBatis-Plus 数据库分页，每页 10 条；项目配置中增加 MyBatis-Plus 分页拦截器。
- 按 `modifytime DESC, id DESC` 排序。相同更新时间时用 ID 保证翻页顺序稳定。

题库：

- 纯数字关键词与题号精确匹配；所有关键词同时对标题和题目描述做包含匹配。
- 使用 MyBatis-Plus 数据库分页，每页 20 条；与博客查询共用分页拦截器。
- 按 `id ASC` 排序。

## 前端交互

博客页 `PkIndexView.vue` 和题库页 `RanKlistIndexView.vue` 分别维护：

- 当前页记录数组；
- `currentPage`、`total`、`totalPages`；
- 搜索关键词、加载状态和错误状态。

页面首次打开时请求 `page=1`。点击上一页、下一页或修改数字输入框后，使用新页码重新请求后端。搜索按钮或回车触发搜索时，将页码重置为 1，并把 `keyword` 放入查询 URL。

数字输入框采用数字类型，默认显示后端返回的当前页，允许使用输入框上下按钮、鼠标滚轮或直接输入跳页。失焦或确认时把小于 1 的值修正为 1，把超过总页数的值修正为最后一页，然后发起请求。

分页控件放在卡片底部右侧：

- 第 1 页禁用左箭头。
- 最后一页或无结果时禁用右箭头。
- 请求进行中临时禁用三个分页控件，避免并发重复请求。
- 搜索请求允许替换仍在进行的旧请求，但只有最新请求的成功、失败和完成回调可以更新页面状态，避免旧响应覆盖新结果。
- 无搜索结果时仍展示空状态，页码显示为 1。

页面顶部和底部的数量文案改用后端返回的筛选后总数。博客详情打开、返回列表、博客整行键盘访问和题目详情跳转行为保持不变。

## 数据流

1. 页面确定页码和搜索关键词。
2. 前端把 `page`、`keyword` 作为 URL 查询参数发给对应接口。
3. 后端校验页码，构造搜索条件和稳定排序，执行分页查询。
4. 后端返回当前页记录和分页元数据。
5. 前端直接替换当前页记录与分页状态，不拼接、不缓存其他页数据。

## 错误与边界处理

- HTTP 请求失败时保留现有错误提示和重试入口；重试失败请求携带的准确页码和关键词。
- 返回结构缺少 `records` 或任一分页元数据、数字范围或页数关系不合法时显示数据格式错误，不沿用上一页旧数据。
- 新搜索、删除数据导致页数收缩或手动输入越界时，以后端返回的修正页码为准。
- 关键词为空时查询全部数据，但仍只返回当前页。

## 测试与验证

后端测试覆盖：

- 博客每页 10 条、题库每页 20 条；
- 博客更新时间倒序及相同时间的 ID 倒序；
- 题号升序；
- 标题、简介或描述关键词筛选，以及数字题号筛选；
- 缺省、非法、越界页码和空结果；
- 响应分页元数据正确。

前端测试覆盖：

- 请求 URL 携带当前页和关键词；
- 初始页、上一页、下一页和数字输入跳页；
- 搜索回到第 1 页；
- 边界按钮禁用；
- 前端只使用响应中的 `records`，不执行全量切片。
