# 本机环境变量与仓库敏感配置迁移设计

## 目标

将当前 Spring Boot 配置中的数据库、RabbitMQ、MinIO 与 Redis 连接信息迁移到本机持久环境变量，保证仓库不再提交真实值，同时让当前用户后续从终端直接启动项目无需再次配置。

## 本机存储

- 真实值保存到 `~/.config/blog-and-oj/env.zsh`，文件权限为 `600`。
- `~/.zshenv` 只包含加载该文件的幂等片段，不直接保存密钥。
- 新启动的 zsh 会自动导出 `BLOG_OJ_*` 环境变量；重新打开从图形界面启动的 IDE 后可继承更新后的登录环境。
- 本机环境文件位于 Git 仓库之外，不会被提交。

## 仓库配置

- 两个 `application.properties` 使用 `${BLOG_OJ_*}` 占位符。
- 数据库、RabbitMQ、MinIO 与 Redis 连接值均来自环境变量；服务端口及超时等非敏感运行参数保留在配置文件中。
- README 记录变量名、持久化位置和验证命令，但不包含真实值。
- `backendcloud/globalCode/` 属于运行时生成内容，加入 `backendcloud/.gitignore` 并从本次提交排除。

## 验证

- 新的登录 zsh 中所有必需变量均非空。
- 仓库配置不再包含上述连接信息的真实值。
- 主后端、判题服务与前端测试通过，前端生产构建成功。
- 提交前扫描暂存差异，确认没有新增明文密码、访问密钥或运行时 `globalCode` 文件。
