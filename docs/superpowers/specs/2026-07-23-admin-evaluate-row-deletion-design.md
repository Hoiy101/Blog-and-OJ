# 后台判例行删除设计

## 目标

在“修改判例”模态框中为每条判例提供清晰的删除操作，并继续使用现有批量保存接口持久化删除结果。

## 交互

- 每个判例卡片右上角显示红色叉号按钮。
- 点击叉号仅从模态框的本地 `rows` 数组中移除对应判例，不立即发送请求。
- 已存在的判例和本次新添加但尚未保存的判例使用相同删除行为。
- 用户点击“保存判例”后，现有提交事件只携带当前仍保留的判例；已删除判例不进入请求列表，由后端删除新列表中缺失的判例。
- 当所有判例均被移除时，展示现有“暂无判例”提示，并保留“添加判例”按钮。
- 关闭模态框而不保存时，不持久化本地删除。

## 组件设计

- 在 `EvaluateModal.vue` 中增加 `removeRow(index)`，通过数组索引移除单条判例。
- 判例标题、ID/新增标记与删除按钮仍位于卡片头部；删除按钮放在右上角操作区。
- 删除按钮使用 Bootstrap 危险色样式，视觉内容为叉号，并提供包含判例序号的 `aria-label`。
- 加载或提交期间禁用删除按钮，避免异步状态下修改表单。
- `ManageTopicsView.vue`、`evaluatePayload` 和现有接口封装无需修改，因为提交数据已经从模态框的当前 `rows` 生成。

## 错误处理

- 本地删除不会产生网络错误。
- 保存失败时继续显示现有模态框错误，当前剩余判例保持在模态框中，用户可修正或重试。

## 测试

- 验证每条判例渲染红色删除按钮及动态无障碍标签。
- 验证 `removeRow(index)` 使用 `splice` 删除指定行。
- 验证删除按钮在提交期间禁用。
- 验证提交仍基于删除后的 `rows` 副本，因此已删除判例不会进入提交列表。
- 运行完整前端单元测试、Lint 和生产构建。

## 非目标

- 不新增或修改后端接口。
- 不在点击叉号时立即发送删除请求。
- 不增加二次确认或撤销按钮。
- 不改动题目删除、判例新增或模态框滚动逻辑。
