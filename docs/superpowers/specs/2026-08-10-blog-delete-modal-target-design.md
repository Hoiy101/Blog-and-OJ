# 个人博客删除弹窗目标修复设计

## 问题与根因

个人中心的博客列表在 `v-for` 中为每篇博客渲染一个删除确认弹窗，但所有删除按钮均使用 `data-bs-target="#romver"`，所有弹窗也均使用 `id="romver"`。重复 DOM ID 使 Bootstrap 始终选择页面中的第一个弹窗，因此确认按钮始终绑定第一篇博客。

## 修复方案

- 为每篇博客的删除弹窗生成唯一 ID：`remove-bot-modal-${bot.id}`。
- 对应删除按钮的 `data-bs-target` 使用同一个动态 ID。
- 删除成功后，`remove_bot(bot)` 使用当前 `bot.id` 获取并关闭正确的弹窗。
- 删除弹窗标题的 `aria-labelledby` 同样改为包含 `bot.id` 的唯一值，避免重复无障碍标识。
- 保留现有删除接口、请求参数、刷新博客列表和确认交互。

## 数据流

1. 用户点击某篇博客的“删除”按钮。
2. 动态 `data-bs-target` 打开该博客对应的唯一弹窗。
3. 弹窗确认按钮调用 `remove_bot(bot)`，传入当前循环项。
4. 请求继续提交 `bot_id: bot.id`。
5. 删除成功后刷新列表并关闭该博客对应的弹窗。

## 测试

- 增加源码回归测试，验证删除按钮目标包含 `bot.id`。
- 验证删除弹窗 ID 与按钮目标使用相同的动态命名规则。
- 验证确认按钮仍将当前 `bot` 传给 `remove_bot`。
- 验证成功回调关闭包含当前 `bot.id` 的弹窗，而不是固定 `#romver`。
- 运行完整前端单元测试、Lint 和生产构建。

## 非目标

- 不改为共享删除弹窗或原生确认框。
- 不修改博客删除后端接口。
- 不重构博客创建、编辑、头像或分页功能。
- 不修改或暂存当前工作区中的其他未提交变更。
