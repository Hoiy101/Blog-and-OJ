# Blog and OJ 后台管理前端设计

## 目标

在现有 Vue 3 前端中实现仅管理员可见、可访问的后台管理功能，包括用户管理、登录记录和题库管理，并与仓库中已经完成的管理端接口对接。

## 范围

本次实现包含：

- 登录用户信息增加管理员标识 `root`。
- 导航栏增加仅管理员可见的“后台管理”下拉菜单。
- 增加用户管理、登录记录、题库管理三个独立页面。
- 增加管理员路由保护。
- 增加后台管理请求与数据转换工具。
- 对关键权限、导航、请求参数和表单转换行为编写单元测试。
- 对 `/user/account/info/` 做一处最小后端修改，使其返回当前用户的 `root` 字段。

本次不包含新增题目、删除题目、删除判例、管理员角色分配、分页后端改造或后台整体侧边栏框架。

## 技术与界面方案

沿用项目现有的 Vue 3、Vue Router、Vuex、jQuery Ajax 和 Bootstrap 5，不引入新的 UI 或请求库。后台功能采用三个独立路由页面，而不是单页标签页或新的后台框架；这样与需求中的三个入口一一对应，也能保持各页面状态相互独立。

页面继续使用项目现有的容器、卡片、表格、按钮和 Bootstrap 弹窗视觉语言。桌面端以表格为主，窄屏时允许表格横向滚动，题目和判例弹窗使用较宽尺寸以容纳多字段表单。

## 权限模型

### 用户状态

Vuex 用户模块增加 `root` 字段，默认值为空字符串。`updateUser` 从登录信息响应中保存 `root`，`logout` 同时清空该字段。管理员判断统一使用严格条件 `root === "true"`，兼容当前后端以字符串存储该字段的模型。

后端 `/user/account/info/` 响应增加 `root`，值直接来自当前登录用户。该修改只补齐前端权限判断所需的数据，不改变其他登录行为。

### 导航与路由

导航栏只在用户已登录且 `root === "true"` 时显示“后台管理”下拉菜单，包含：

- 用户管理
- 用户登录信息
- 题库管理

三个后台路由同时设置 `requiresAuth: true` 和 `requiresAdmin: true`。全局路由守卫先处理未登录用户，再处理非管理员用户；未登录用户进入登录页，已登录但非管理员的用户返回首页。隐藏菜单不是唯一权限控制手段。

## 路由与页面

### 用户管理 `/manage/users/`

页面加载 `/manage/user/gitlist/`，展示：

- 用户名
- 身份：管理员或普通用户
- 状态：正常或已封禁
- 操作

每行显示与当前状态匹配的主要操作。后端的实际语义是 `status=0` 封禁、`status=1` 解封，因此前端按该语义发送参数；这与需求文档中的数字描述相反，但可确保按钮实际效果正确。操作成功后重新调用用户列表接口，以服务器状态为准刷新表格。管理员也使用相同操作规则，不在前端额外制造后端没有定义的限制。

### 登录记录 `/manage/login-records/`

页面加载 `/manage/record/login/`。由于当前后端返回全部记录，前端将合法记录按登录时间从新到旧排序并截取前 100 条，展示：

- 用户名
- 登录 IP
- 登录时间

如果时间无法解析，则保留服务器返回顺序中的相对位置，不因单条异常导致整页失败。

### 题库管理 `/manage/topics/`

页面加载 `/oj/topic/getlist/`，列表只展示：

- ID
- 标题
- 难度 `star`
- “修改题目”按钮
- “修改判例”按钮

可提供前端标题或 ID 搜索，以便定位题目，但不改变服务端数据。

#### 修改题目弹窗

打开弹窗时使用题目 ID 调用 `/oj/topic/get/`。表单包含后端可更新的全部非 ID 字段：

- `test_point`：测试点数量，正整数
- `title`：标题，必填且不超过 100 个字符
- `description`：题目描述，必填
- `star`：难度
- `time_limit`：时间限制，正整数
- `mem_limit`：内存限制，正整数
- `input_format`：输入格式
- `output_format`：输出格式
- `sample_input`：样例输入
- `sample_output`：样例输出
- `hint`：提示

提交时额外携带只读的 `topic_id`，使用表单编码调用 `/oj/topic/updata/`。成功后关闭弹窗并重新加载题目列表；失败时保留用户输入并在弹窗内显示后端 `error_message`。

#### 修改判例弹窗

打开弹窗时以 `topic_id` 调用 `/manage/evaluate/get/`。每条判例显示序号、输入和输出，已有判例保留 `id`，题号由当前题目统一提供。点击“添加判例”会在末尾追加一条没有 `id`、输入输出为空的本地记录。

提交时将每条记录转换为后端需要的对象：

- 已有判例：`id`、`topic_id`、`input`、`output`
- 新增判例：`topic_id`、`input`、`output`，不发送 `id`

完整数组以 JSON 调用 `/manage/evaluate/updata/`。前端先阻止空输入或空输出提交，后端业务错误仍显示在弹窗内。当前后端接口不支持删除判例，因此界面不提供删除按钮。

## 请求与数据边界

建立聚焦于后台管理的请求模块，统一负责：

- 从 Vuex token 生成 `Authorization: Bearer <token>` 请求头。
- 调用用户、登录记录、题目和判例管理所需的全部接口。
- 将网络失败转换为适合界面展示的错误文本。
- 保留服务器业务响应，由页面判断 `error_message === "success"`。

纯数据逻辑与 Vue 组件分离，包括管理员判断、登录记录排序截取、封禁状态参数映射、题目表单默认值和判例提交数据转换。这样可以使用当前项目已有的 Node 内置测试运行方式直接测试核心行为，不依赖浏览器或额外测试框架。

## 状态与错误处理

每个页面维护独立的加载、错误和数据状态：

- 首次加载显示加载状态。
- 网络或鉴权失败显示错误和重试按钮。
- 空数组显示明确的空数据提示。
- 修改请求进行中禁用提交或状态按钮，避免重复发送。
- 业务失败保留当前页面或弹窗状态，并显示服务器消息。
- 操作成功后以重新请求的数据为准，不对关键状态做长期乐观更新。

题目和判例弹窗分别维护加载与提交状态。关闭弹窗时清理旧错误和表单数据，避免切换题目时出现上一次内容闪现。

## 测试与验收

实现遵循测试先行，覆盖以下行为：

- `root` 能写入和清空用户状态。
- 只有 `root === "true"` 被识别为管理员。
- 后台导航项受管理员状态控制。
- 后台路由包含管理员元数据，路由守卫拒绝非管理员。
- 封禁映射为 `status=0`，解封映射为 `status=1`。
- 登录记录按时间倒序且最多返回 100 条。
- 题目详情能转换为完整编辑表单与更新参数。
- 新增和已有判例能转换为正确 JSON 载荷，新增记录不带 `id`。

最终验收运行：

- `npm run test:unit`
- `npm run lint`
- `npm run build`

并在浏览器中检查管理员与普通用户的导航差异、三个后台页面、两种弹窗、窄屏表格滚动，以及成功和失败反馈。

## 完成标准

- 管理员登录后能从导航进入三个后台页面。
- 普通用户看不到入口，也不能通过直接输入 URL 进入后台页面。
- 用户封禁与解封后列表状态正确刷新。
- 登录记录最多展示最新 100 条。
- 题目所有可更新字段都可编辑并提交。
- 判例可批量编辑并追加新记录后提交。
- 所有自动化检查通过，生产构建成功。
