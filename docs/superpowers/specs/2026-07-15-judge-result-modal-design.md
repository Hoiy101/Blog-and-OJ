# 判题结果模态框交互设计

## 目标

简化题目判题界面的反馈方式。提交代码后，在尚未收到结果期间只让提交按钮保持禁用并显示转圈状态；页面不再展示按钮下方的“提交结果”信息。收到正式判题结果或 HTTP 提交失败时，统一通过模态框向用户反馈。

## 范围

本次只修改前端判题详情页及现有结果模态框，不修改后端接口、WebSocket 协议、代码编辑器或测试用例展示逻辑。

## 交互状态

### 初始状态

- 提交按钮显示“提交代码”，可以点击。
- 结果模态框隐藏。
- 提交按钮下方不显示判题状态信息。

### 等待判题

- 用户提交非空代码后，按钮立即禁用并显示转圈。
- HTTP 请求成功只表示提交已被接受，按钮继续转圈。
- 在 WebSocket 返回有效判题消息之前，不显示任何判题状态文本或模态框。

### 判题完成

- WebSocket 消息同时包含 `score` 和 `state` 时，视为有效判题结果。
- 收到有效结果后立即停止按钮转圈，并将消息映射到现有结果模态框。
- 模态框展示分数、状态和判题记录 ID，并沿用现有关闭和查看题解操作。
- 无关消息或无法解析的消息不弹窗，也不改变等待状态。

### HTTP 提交失败

- HTTP 请求失败时立即停止按钮转圈。
- 使用同一个结果模态框展示提交错误，但采用独立的错误标题、说明和危险样式。
- 优先显示后端响应中的错误信息；没有可用信息时显示“提交失败，请稍后重试”。
- 错误模态框不展示无意义的分数、判题记录 ID 或“查看题解”按钮，关闭按钮文案为“返回修改”。

## 组件设计

### `QuestionDetails.vue`

- 删除 `submissionResult` 状态及按钮下方的提交结果模板。
- 删除只为该区域服务的 `getResultAlertClass` 和结果文案映射。
- HTTP 成功回调不再修改界面状态。
- HTTP 错误回调构造提交错误数据、停止转圈并打开模态框。
- HTTP `complete` 回调不再无条件停止转圈。
- WebSocket 有效消息回调停止转圈并打开正式判题结果模态框。

### `ResultModal.vue`

- 继续作为所有提交反馈的唯一模态框。
- 支持 `submission_error` 状态和可选的 `message` 字段。
- 根据状态控制分数、详情和查看题解按钮是否展示。
- 正式判题结果的现有展示保持不变。

## 错误信息提取

错误信息按以下优先级选择：

1. `responseJSON.message`
2. `responseJSON.error`
3. `responseText`
4. 固定回退文案“提交失败，请稍后重试”

空字符串和非字符串值不作为有效错误信息。

## 测试

前端单元测试覆盖以下行为：

- 模板中不存在按钮下方的提交结果区域。
- HTTP 成功后仍保持等待状态，不提前弹出模态框。
- HTTP 失败后停止转圈，并用错误模态框展示可用错误信息或回退文案。
- 有效 WebSocket 判题结果停止转圈并打开结果模态框。
- 无效 WebSocket 消息不改变等待状态。
- `ResultModal` 在提交错误状态下隐藏分数、记录详情和查看题解按钮。

## 非目标

- 不增加判题超时计时器。
- 不修改 MinIO、博客或 Markdown 功能。
- 不修改后端错误响应结构。
- 不实现 WebSocket 自动重连。
